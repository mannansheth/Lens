# Repository discovery, parsing, and indexing

Indexing begins with a deterministic directory walk. Lens excludes common virtual environments, package trees, generated/build outputs, caches, and third-party directories. It applies `.gitignore` and `.lensignore` patterns while retaining project documentation under documentation folders, essential configuration, and supported application-settings files when those are ignored by broad repository rules. Lockfiles, minified assets, source maps, and unsupported JSON datasets are not indexed as application configuration. For the full explanation of why these boundaries exist and how each stage connects to RAG, see [How Lens understands a project and answers questions](rag-pipeline.md).

Parsers are dispatched by file type. The current adapters include C#, JavaScript/TypeScript, HTML, CSS, Python, Razor, SQL, .NET project metadata, structured configuration, and project documents (`.md`, `.mdx`, `.rst`, `.adoc`, `.txt`). Documentation is split into heading-based sections with source line ranges and document metadata. Configuration is parsed as evidence; sensitive values are redacted from answer evidence and traces. Parsing is static: it extracts recognized structure and literal relationships without executing the target application.

Parsers emit files, symbols, relationships, and warnings. A resolution pass connects references that can be established conservatively. Unresolved references remain unresolved rather than being promoted to confirmed edges. Chunk construction creates one main retrieval document per non-namespace entity and concise embedding inputs. FastEmbed generates dense vectors locally; exact input hashes, model, and dimensions allow unchanged vectors to be reused, including after compatible pipeline revisions. A refresh reparses the snapshot; embedding reuse does not mean only changed entities are persisted. The project snapshot is replaced transactionally so a failed indexing operation does not leave a partial index.

The current index pipeline revision is `whole-application-v6-navigation-retrieval`. A revision change invalidates the unchanged-index fast path, while embeddings whose exact input text, model, and dimensions still match can be reused.

Check the `files_scanned`, `files_ignored`, `files_skipped`, `files_indexed`, `chunks`, `relationships`, `embeddings_generated`, and `embeddings_reused` values returned by `lens index`. They are repository-specific measurements and should be recorded with the repository state and settings if used in an evaluation.
