# Retrieval and answer generation

Lens retrieves from its project-scoped PostgreSQL index using lexical search and dense-vector similarity. Hybrid search combines candidates from both paths with weighted reciprocal-rank fusion (RRF constant 60), then applies stable query-aware priorities for relationship/API/UI-route matches, exact identifiers, source scope, and entity kind. `alpha` weights the lexical and vector branch ranks; it defaults to 0.5. Document selection can reserve directly topic-matched documentation alongside code, but repository-specific synonyms and document/navigation numeric score boosts are not used. The hybrid score by itself is not the final rank. Search debug output exposes candidate scores and signals so retrieval decisions can be inspected. See [How Lens understands a project and answers questions](rag-pipeline.md) for the full theoretical explanation and end-to-end flow.

For questions about how behavior flows across files, evidence expansion follows resolved edges within depth and context limits. Unresolved relationships are retained as uncertain references rather than treated as established calls. Context construction selects bounded excerpts, source locations, relationship descriptions, and compact citation identifiers. The answer provider receives this context instead of the entire repository. Documentation can be selected alongside code; document dates/status are source metadata and do not independently establish freshness.

The answer layer supports the Ollama adapter and optional Gemini adapter. It requests structured output, validates response shape, intent, and citations, then maps citations back to file paths and lines. This validation catches malformed or unsupported structures but cannot prove semantic entailment for every claim. Static analysis also cannot establish live state, runtime authorization, or execution success.

Use `lens search ... --debug` to inspect retrieval and `lens ask ... --json` to inspect structured answers. For labeled evaluation, `lens evaluate labels.json --diagnostics` separates candidate coverage from ranking/selection loss; `--candidate-limit N` lets you test wider branch pools without changing the default. Retrieval recall and citation validity should be evaluated separately from answer correctness and usefulness. See [validation](validation.md).
